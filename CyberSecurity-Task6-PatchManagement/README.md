# Task 6 – The Importance of Patch Management

## Overview

This project presents a research-based report explaining the importance of patch management in cybersecurity.

Patch management is the process of identifying, assessing, testing, deploying, and verifying software updates and security patches. It plays an important role in reducing vulnerabilities and minimizing an organization's attack surface.

The report examines how vulnerabilities are discovered and catalogued using CVEs, how unpatched vulnerabilities can be exploited, and how organizations can implement an effective patch-management strategy.

---

## Objectives

The main objectives of this task are to:

- Understand what patch management is.
- Understand the role of patch management in the vulnerability lifecycle.
- Learn how vulnerabilities are identified and catalogued using CVEs.
- Understand CVSS vulnerability severity scoring.
- Analyse the risks of unpatched systems.
- Study real-world incidents involving unpatched vulnerabilities.
- Understand the patch-management lifecycle.
- Develop a practical seven-step patch-management checklist.
- Identify common patch-management challenges and their solutions.

---

## Topics Covered

### 1. Patch Management

The report explains patch management and its role in reducing security vulnerabilities throughout an organization's technology environment.

### 2. CVE and CVSS

The report explains:

- Common Vulnerabilities and Exposures (CVE)
- Common Vulnerability Scoring System (CVSS)
- Vulnerability severity and risk-based prioritization

### 3. Real-World Security Incidents

Two major incidents are analysed:

- WannaCry ransomware and the EternalBlue vulnerability
- 2017 Equifax data breach

These incidents demonstrate the potential consequences of failing to patch vulnerable systems.

### 4. Consequences of Not Patching

The report discusses:

- Data breaches
- Ransomware attacks
- Operational disruption
- Compliance violations
- Financial losses and penalties
- Reputational damage

### 5. Patch Management Lifecycle

The report follows five major phases:

```text
Discovery
    ↓
Assessment
    ↓
Testing
    ↓
Deployment
    ↓
Verification
```
## 6. Seven-Step Patch Management Checklist

The report provides a prioritized checklist covering:

1. Maintain an accurate asset inventory.
2. Continuously identify vulnerabilities.
3. Prioritize vulnerabilities based on risk.
4. Test important patches.
5. Deploy patches promptly.
6. Verify and document patch installation.
7. Review exceptions and continuously improve the process.

---

## 7. Patch Management Challenges

The report discusses challenges such as:

- Legacy systems
- Downtime concerns
- Testing requirements
- Large and distributed environments
- Lack of asset visibility

Practical solutions are provided for each challenge.

---

## Key Recommendations

Organizations should:

- Maintain an accurate inventory of hardware and software.
- Continuously monitor for newly discovered vulnerabilities.
- Prioritize critical and actively exploited vulnerabilities.
- Test patches appropriately before large-scale deployment.
- Deploy security updates promptly.
- Verify that patches were successfully installed.
- Document systems that cannot be patched.
- Use compensating controls for systems that cannot be immediately updated.
- Continuously review and improve the patch-management process.

---

## Conclusion

Patch management is an essential part of cybersecurity because unpatched vulnerabilities can provide attackers with opportunities to compromise systems.

Organizations can reduce their attack surface by maintaining accurate asset inventories, identifying vulnerabilities, prioritizing risks, testing patches, deploying updates promptly, and verifying successful remediation.

A structured patch-management process helps reduce the likelihood of data breaches, ransomware attacks, operational disruption, and other security incidents.
